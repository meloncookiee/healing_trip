# Healing Trip Gyeonggi — 개발 계획

근거 문서: `docs/PRD.md`  
실행 기준: 기존 보일러플레이트(`frontend/` React+Vite, `backend/` FastAPI) + conda 환경 `youthhub`  
아키텍처: 프론트는 FastAPI만 호출 → 서버가 공공데이터 API 호출·정제 → SQLite 저장 후 제공

---

## 0. 현재 상태 (확인 완료)

이미 준비된 것 (계획에서 **제외**)

- `frontend/` — React + Vite 보일러플레이트
- `backend/` — FastAPI 기반 백엔드 자리
- `docs/` — PRD 등 기획 문서
- conda 환경 `youthhub`
- `.env` 기반 비밀값 관리 전제

이번 계획의 시작점: **기능 구현 (데이터 모델 → 공공 API 연동 → API → UI)**

참고: PRD의 Next.js / Redis / API Routes 스택은 본 프로젝트 구조와 다르다.  
실제 구현은 **React(Vite) + FastAPI + SQLite**로 진행한다.

---

## 1. 개발 원칙

1. **한 번에 하나의 기능**만 구현한다.
2. **백엔드 완료 → 프론트 연결** 순서를 기본으로 한다.
3. 프론트는 공공데이터 API를 **직접 호출하지 않는다**.
4. MVP를 먼저 완성하고, 지역 필터·지도·즐겨찾기는 **추가 개발**로 미룬다.
5. 두 API 응답을 `Temple` / `Attraction` 공통 모델로 표준화한다.

---

## 2. MVP 범위 정의

### MVP에 포함

| 영역 | 내용 |
|------|------|
| 템플스테이 | 전체 목록, 상세 조회 (사찰명·주소·연락처·소개·프로그램) |
| 자연관광지 | 목록, 상세 조회, 카테고리별 조회 (명칭·주소·설명·이미지) |
| 검색 | 사찰명·관광지명 키워드 검색 |
| 필터 | 관광 유형 필터 (지역 필터는 제외) |
| 주변 추천 | 템플스테이 선택 시 반경 N km 관광지 추천 |
| 상세 페이지 | 템플스테이 / 관광지 각각의 상세 UI |
| 안정성 | 로딩·에러·빈 결과 Fallback UI |

### MVP에서 제외 → 추가 개발

- 지역 필터
- 지도 서비스 (표시·현재 위치·마커)
- 즐겨찾기

### Out of Scope (PRD 기준, 이번 로드맵 밖)

회원가입·로그인·예약·결제·리뷰·평점·커뮤니티·AI 추천·일정 저장·SNS 공유

## 3. 전체 개발 순서 개요

```

    ↓
[Phase C] 백엔드 조회 API (목록·상세·검색·카테고리·주변)
    ↓
[Phase D] 프론트엔드 MVP UI (목록·상세·검색·카테고리·주변)

    ↓
[Phase F] 추가 개발 — 지역 필터
    ↓
[Phase G] 추가 개발 — 지도
    ↓
[Phase H] 추가 개발 — 즐겨찾기
```

## 4. Phase별 상세 계획

### Phase A — 백엔드 기반

**목표:** SQLite에 저장할 공통 스키마와 FastAPI 앱 뼈대를 이 서비스에 맞게 정리한다.

작업 내용

- `.env`에 경기도 템플스테이·관광정보 API 키/베이스 URL 설정 (하드코딩 금지)
- `Temple`, `Attraction` SQLite 테이블/모델 정의
  - Temple: id, name, address, phone, description, program, lat/lng(가능 시), region 등
  - Attraction: id, name, address, description, image_url, category, lat/lng 등
- DB 초기화·연결 유틸
- CORS 등 프론트(`Vite`) 연동에 필요한 최소 설정 확인

완료 기준

- 서버 기동 가능
- 빈 테이블이 생성된 상태

---

### Phase B — 공공데이터 수집·저장

**목표:** 외부 API → 정제 → SQLite 적재 파이프라인을 만든다.

#### B-1. 경기도 템플스테이 API

- 클라이언트: `https://openapi.gg.go.kr/Templestay`
- 응답을 `Temple` 스키마로 매핑
- 동기화(동기/배치) 엔드포인트 또는 기동 시 적재 로직
- 실패 시 로그·재시도 가능한 수준의 에러 처리

#### B-2. 한국관광공사 관광정보 API

- 클라이언트: 관광정보 Open API (자연관광 중심)
- 응답을 `Attraction` 스키마로 매핑 (이미지·좌표 포함)
- 경기도(또는 MVP 범위 지역) 데이터로 범위 한정
- SQLite upsert

완료 기준

- DB에 템플스테이·관광지 레코드가 실제로 쌓임
- 프론트 없이 API/DB만으로 데이터 확인 가능

---

### Phase C — 백엔드 조회 API (MVP)

**목표:** 프론트가 쓸 REST API를 제공한다. (공공 API 직접 노출 금지)

구현 순서

1. `GET /temples` — 템플스테이 목록
2. `GET /temples/{id}` — 템플스테이 상세
3. `GET /attractions` — 관광지 목록 (+ 카테고리 쿼리)
4. `GET /attractions/{id}` — 관광지 상세
5. `GET /search?q=` — 사찰명·관광지명 통합(또는 타입별) 키워드 검색
6. `GET /temples/{id}/nearby?radius_km=N` — 주변 관광지 추천 (좌표 기반)

공통

- 응답 스키마 일관화 (필드명·null 처리)
- 검색/목록 성능은 SQLite 인덱스·간단 페이징으로 MVP 충족
- 외부 API 장애와 무관하게 **DB 조회**로 응답 (수집은 별도)

완료 기준

- Swagger/브라우저로 위 엔드포인트 검증 완료

---

### Phase D — 프론트엔드 MVP UI

**목표:** FastAPI만 호출하는 React 화면을 만든다.

구현 순서

1. API 클라이언트 정리 (`frontend/src`에서 백엔드 베이스 URL 호출)
2. 라우팅: 홈 / 템플스테이 목록·상세 / 관광지 목록·상세 / 검색
3. 템플스테이 목록·상세 페이지
4. 관광지 목록·상세 페이지 (이미지·카테고리 표시)
5. 키워드 검색 UI
6. 관광 유형(카테고리) 필터 UI
7. 템플스테이 상세에서 주변 관광지 추천 섹션
8. 로딩·에러·결과 없음 Fallback UI
9. 모바일 우선 기본 레이아웃 (과도한 디자인 시스템 도입은 하지 않음)

완료 기준

- 사용자가 목록 → 상세 → 주변 추천까지 끊김 없이 탐색 가능
- 브라우저 네트워크 탭에 공공데이터 직접 호출이 없음

---

### Phase E — MVP 통합 점검

- 데이터 동기화 → 목록/검색/상세/주변 추천 E2E 확인
- PRD NFR 중 MVP에서 현실적으로 확인할 항목
  - 목록·검색 응답이 과도하게 느리지 않은지
  - API 키 서버 사이드 관리 여부
  - 장애 시 Fallback UI 동작
- `docs/TASKS.md` MVP 체크리스트 완료 표시

## 5. 추가 개발 (MVP 이후)

지시가 있을 때까지 구현하지 않는다. 순서만 고정한다.

### Phase F — 지역 필터

**백엔드**

- Temple/Attraction의 지역 필드 정규화
- `region` 쿼리 파라미터 지원 (목록·검색)

**프론트**

- 지역 선택 UI
- 목록·검색 결과에 지역 필터 반영

---

### Phase G — 지도

**백엔드**

- 목록/상세/주변 API 응답에 lat/lng 안정적 제공
- (필요 시) 지도용 경량 좌표 전용 엔드포인트

**프론트**

- 지도 SDK 연동 (예: Kakao Maps)
- 템플스테이·관광지 마커 표시
- 현재 위치 표시
- 템플스테이 선택 시 주변 관광지 지도 연동
- 마커 다수 시 클러스터링 검토

---

### Phase H — 즐겨찾기

**백엔드**

- 즐겨찾기 저장 API (로그인 없이 로컬 식별 또는 단순 저장 방식은 구현 시점에 결정)
- 목록 조회·추가·삭제

**프론트**

- 상세/목록에서 즐겨찾기 토글
- 즐겨찾기 목록 페이지

## 7. 권장 구현 리듬

매 작업 단위:

1. `docs/TASKS.md`에서 **한 항목** 선택
2. 백엔드면 API/DB까지 검증 → 프론트면 화면·호출까지 검증
3. 해당 체크박스 완료 표시
4. 변경 파일·실행 확인 방법을 짧게 기록

금지

- scaffold / 새 conda 환경 생성
- MVP 중 지역 필터·지도·즐겨찾기 선행 구현
- 프론트에서 공공 API 직접 호출
- 비밀값 하드코딩
